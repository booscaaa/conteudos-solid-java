Interface Segregation Principle — o "I" do SOLID
Interfaces pequenas e coesas, sem métodos que ninguém usa.

Contexto

A Definição

O que diz o ISP?

format_quote

"Nenhuma classe deve ser forçada a implementar métodos que não utiliza."

— Robert C. Martin

🍕
Interface Gorda
Uma interface com muitos métodos.
Clientes são forçados a depender de métodos que não precisam.
✂️
Interfaces Segregadas
Interfaces pequenas e focadas.
Cada cliente depende apenas do que realmente usa.
lightbulb ISP não é sobre interfaces com um único método — é sobre interfaces coesas: cada uma com uma razão de existir.
O Problema

A Impressora Gordinha 🖨️

Interface Gorda — PROBLEMA

interface Impressora { void imprimir(String doc); void escanear(String arquivo); void enviarFax(String num, String doc); void imprimirColorido(String doc); void copiar(int copias); }

Classe forçada a implementar tudo

class ImpressoraBasica implements Impressora { public void imprimir(String d) { System.out.println(d); // OK } public void escanear(String a) { throw new UnsupportedOperationException(); } public void enviarFax(String n, String d) { throw new UnsupportedOperationException(); } // ... mais 2 métodos "mentindo" }
warning ImpressoraBasica tem 5 métodos, usa 1. Os outros 4 estão lá para enganar quem usa a interface.

Debugger Interativo

O que acontece em runtime?

A Solução

Segregar em interfaces menores

Interfaces Coesas — SOLUÇÃO

interface Imprimivel { void imprimir(String d); } interface Escaneavel { void escanear(String a); } interface Enviavel { void enviarFax(String n, String d); } interface Colorivel { void imprimirColorido(String d); } interface Copiavel { void copiar(int n); }

Cada classe só implementa o que faz

// Só imprime — honesta! class ImpressoraBasica implements Imprimivel { public void imprimir(String d) { /* OK */ } } // Imprime, escaneia e copia class Multifuncional implements Imprimivel, Escaneavel, Copiavel { // ... só o que realmente faz } // Tudo — também honesta! class ImpressoraEmpresarial implements Imprimivel, Escaneavel, Enviavel, Colorivel, Copiavel { }
check_circle Zero UnsupportedOperationException. Nenhuma classe implementa o que não pode fazer.
Exemplo 2

Trabalhador vs. Robô 🤖

Violação

interface Trabalhador { void trabalhar(); void comer(); // robô não come! void dormir(); // robô não dorme! } class Robo implements Trabalhador { public void trabalhar() { /* ok */ } public void comer() { throw new UnsupportedOperationException(); } public void dormir() { throw new UnsupportedOperationException(); } }

ISP Aplicado

interface Trabalhavel { void trabalhar(); } interface Alimentavel { void comer(); } interface Descansavel { void dormir(); } // Humano faz tudo class Humano implements Trabalhavel, Alimentavel, Descansavel { public void trabalhar() { /* trabalha */ } public void comer() { /* come */ } public void dormir() { /* dorme */ } } // Robô só trabalha — honesto! class Robo implements Trabalhavel { public void trabalhar() { /* trabalha */ } }
Exemplo Avançado

Repository Segregado

Interface Monolítica

interface Repository<T> { T findById(Long id); List<T> findAll(); void save(T entity); void delete(Long id); List<T> findByFilter(Filter f); void bulkSave(List<T> entities); // isso não é responsabilidade do repo! void exportToCsv(String path); }

Interfaces Segregadas

interface ReadRepository<T> { T findById(Long id); List<T> findAll(); } interface WriteRepository<T> { void save(T entity); void delete(Long id); } interface FilterableRepository<T> extends ReadRepository<T> { List<T> findByFilter(Filter f); } // Combina leitura e escrita interface FullRepository<T> extends ReadRepository<T>, WriteRepository<T> { }
info Um repositório somente leitura implementa ReadRepository. Um cache implementa WriteRepository. Sem nenhum método lançando exceção.
Como Identificar

Sinais de Violação do ISP

1

UnsupportedOperationException em métodos de interface

Se você lança exceção para "cumprir" o contrato, a interface está errada, não a implementação.

2

Métodos com corpo vazio { /* não faz nada */ }

Silencioso e perigoso — cliente chama o método e nada acontece.

3

Clientes que usam 1–2 métodos de uma interface com 10

Se o cliente só usa findById() de um Repository com 8 métodos, ele depende de muito mais do que precisa.

4

Interfaces com nomes vagos: Manager, Handler, Service, Util

Nomes vagos geralmente indicam responsabilidades misturadas — sintoma de interface gorda.

5

Mudar a interface quebra classes que não usam o método novo

Adicionar exportToCsv() a um Repository força todas as implementações a mudar.

Regra Prática

Interface deve ter 1 razão para mudar

Assim como o SRP diz que uma classe deve ter uma razão para mudar, uma interface segregada deve mudar apenas quando a capacidade que ela representa muda.

// Pergunte-se: quem muda se eu alterar esta interface? // Se MUDAR Imprimivel → só afeta quem imprime ✓ interface Imprimivel { void imprimir(String d); } // Se MUDAR Escaneavel → só afeta quem escaneia ✓ interface Escaneavel { void escanear(String a); } // Se MUDAR Impressora (gorda) → afeta TODOS ✗ interface Impressora { /* 5 métodos... */ }
rule Tamanho ideal: não existe número mágico. Uma interface com 3 métodos altamente coesos é melhor que 3 interfaces de 1 método artificialmente separados.
groups Perspectiva do cliente: projete a interface com base em quem vai usá-la, não em quem vai implementá-la.
Conexões

ISP e os outros SOLID

S
SRP
Interfaces coesas têm uma única razão para mudar, assim como classes SRP. ISP é o SRP aplicado a interfaces.
L
LSP
Interfaces pequenas tornam mais fácil implementações honestas. Menos chance de lançar UnsupportedOperationException e violar o LSP.
D
DIP
Depender de interfaces pequenas é mais estável. Uma mudança na interface gorda força recompilação de tudo que depende dela.
link Na prática: ISP e LSP caminham juntos. Uma interface bem segregada previne implementações que precisam mentir sobre o que podem fazer.

Resumo

Interface Segregation em 4 pontos

call_split

Prefira interfaces pequenas

Cada interface representa uma capacidade específica. Uma classe que imprime não deve conhecer scanner nem fax.

warning

UnsupportedOperationException = sinal de alerta

Se você lança exceção para "cumprir" a interface, a interface está errada, não a implementação.

person

Projete pelo cliente, não pelo implementador

Quem usa a interface deve ditar sua forma. O cliente que só lê não precisa saber que save() existe.

link

Interfaces se compõem via herança

Use interface FullRepo extends ReadRepo, WriteRepo para combinar capacidades sem perder coesão.
